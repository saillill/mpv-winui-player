# b1 vs b2 决策记录（草案，P0/L5）

> 状态：审查草案。L1/L2 的实机核验项按用户指示暂停，定稿需补测。

## 背景

- b1a：mpv 内建菜单（menu-data/context-menu，Lua 运行时探测，mpv ≥0.37 类构建）。
- b1b：menu.dll（tsl0922/mpv-menu-plugin，C 插件 + 系统 Win32 TrackPopupMenu，本仓为本地重编译版）。
- b2：MpvMenuHost.exe（独立 WinUI 3 进程，自包含 .NET 10 + WAS 2.3.1，逐级进程 + 预热链）。

现状：`dyn_menu.conf` 默认 `host_menu=yes`（b2）；b1b 作为回退存在。

## 能力对比（基于代码/文档/已跑测试，实机项待补）

| 维度 | b1a/b1b | b2 | 备注 |
|---|---|---|---|
| 运行时依赖 | 零新增（系统 Win32） | .NET10 + WAS 自包含 266.5MB×2 | b2 违反原则 0 |
| 常驻内存 | 0（随菜单创建） | 每级 124–125MB ×3 | b2 高 |
| Win11 观感（圆角/亚克力/动画/级联重叠） | 系统菜单自带 | 手写实现 | 用户要的重叠+动画，系统已提供 |
| 条目图标 | menu.dll 当前不渲染（HMENU 支持 bitmap/owner-draw，可扩展） | 157+47 码点全覆盖 | b2 唯一明确增量 |
| 稳定性记录 | 宽度缓存 bug（本地重编译已修）；无自绘窗口类 bug | 白框闪/置顶闪烁/转圈/三级方向等自绘 bug 历史 | b2 问题为自绘引入 |
| 动态菜单 | Lua 更新 menu-data 驱动 | JSON→IPC 文件链 | 各有实现 |
| 维护面 | 上游仓库 + 本地补丁 | 全套自研 + 双份 266MB 同步 | b2 重 |

## 缺口清单（L1，实机核验后补全）

- 已确认：menu.dll 不渲染条目图标。
- 待核验：键盘导航/ESC/点外关闭在 b1 原生路径的表现、动态菜单刷新延迟、多屏 DPI。
- 待核验：b1a（内建 menu-data）在本 mpv-lazy 构建是否可用。

## 收益量化（L2，草案）

- b2 相对 b1 的增量收益：条目图标（用户要求）+ 自绘观感可控。
- b2 成本：266.5MB×2、每会话 ≈374MB 常驻、全部自绘 bug 修复投入、WAS/.NET 升级义务。
- 结论（草案）：收益不足以支撑默认 b2；建议 b2 降级为显式可选实验。

## 建议（L3）

1. 发布默认 `host_menu=no`（走 b1b；若目标构建支持内建菜单可先验证 b1a）。
2. b2 保留在仓库作为可选增强，`host_menu=yes` 由用户显式开启并自行承担体积。
3. 若图标是硬需求：优先评估在 menu.dll 增加 HMENU bitmap/owner-draw 图标（仍零新增运行时），而非默认自绘。
