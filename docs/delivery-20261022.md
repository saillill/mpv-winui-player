## 4 云端差异：结论与直觉相反

```
git rev-list --left-right --count cloud/main...HEAD   ->  0  116
git merge-base cloud/main HEAD                        ->  3053352（= 云端 HEAD）
```

**本地是云端的严格后继**。云端**没有任何**本地缺失的提交——所以「云端已有而本地遗漏」
在提交层面不可能发生。剩下的风险是「本地在 116 个提交里删坏了云端的东西」，
审计用两条证据排除：

1. 11 个被删文件逐个查到零悬空引用（`git grep` exit=1），且都有替代实现。
2. 27 行功能矩阵：**0 项需要从云端移植，0 项需要回退**。

**一处真实发现**：`README.md` 声称支持 `osc-preview-api` 插件，而
`git grep -i osc-preview` 在**云端和本地都只命中 README 那一行**——两端都没有实现。
这是文档过度声称，不是可移植功能。顺带订正：thumbfast 走自己的 `script-message`
协议，**不是** `osc-preview-api`；后者是 mpv 内置 `osc.lua` 的接口，而本项目 `osc=no`。

## 6 MCP：常规验证不再依赖手动点击

`tools/mvpw-mcp/` 是一个 stdio JSON-RPC 的 MCP server，8 个工具：

| 工具 | 作用 |
|---|---|
| `launch_app` | 从 mpv-deploy 启动，等窗口 |
| `close_app` | 先 `WM_CLOSE`，不响应才强杀 |
| `get_ui_snapshot` | UIA 树：AutomationId / 类型 / 可用 / 矩形（**Name 默认脱敏**——库卡片会带出用户片名） |
| `invoke_control` | invoke / select / expand / collapse / toggle / click |
| `assert_element_state` | 存在 / 可用 / 可见 / 名称，返回 problems 而非抛异常 |
| `screenshot_region` | 窗口 / 元素 / 矩形 → PNG（诊断用，不是判据） |
| `read_playback_state` | 走 `\\.\pipe\mpvpipe` 读 pause / time-pos / volume 等 |
| `trigger_screenshot` | 让 mpv 自己 `screenshot-to-file` |

注册方式：

```json
"mvpw": { "command": "python",
          "args": ["<repo>/tools/mvpw-mcp/mcpw_server.py"] }
```

**实测证据**（不是「应该能用」）：

| 脚本 | 结果 |
|---|---|
| `verify_e2e.py` | **19/19** — 启动 → 5 项外壳断言 → 四次导航+断言 → 播放状态 → 截图 → 关闭 → 断言无进程 |
| `verify_mcp_protocol.py` | **9/9** — 真实 JSON-RPC：initialize / tools/list / 一个必须失败的调用 / launch+assert+invoke+snapshot+close / 未知方法报错 |
| `verify_settings.py` | 33 个 AutomationId，`OptionListView` 存在，两窗关闭，无残留进程 |
| `verify_skins.py` | 三套皮肤下播放键都能翻转 `pause` |
| `verify_skin_geometry.py` | 五控件在三套皮肤下几何各不相同 |
| `verify_screenshot.py` | 写出 70 KB PNG |

**过程中发现并修掉的自身缺陷**：`trigger_screenshot` 第一版把 `"png"` 当第三个参数
传给 `screenshot-to-file`，而那个位置是 **mode flags**（`subtitles`/`video`），格式是
`screenshot-format` 属性——mpv 返回 `invalid parameter`，工具却报成功。这正是
「只验证自己用到的路径」会留下的洞。

**为让它可测，应用改了一行**：导航项原本没有 `AutomationId`，只能按本地化标题定位
（换语言就失效）。`9f27024` 用 `AutomationProperties.SetAutomationId` 补
`ShellNav_<key>`。注意 `NavigationViewItem.AutomationId` **不能**在对象初始化器里写
（CS0117，附加属性才是对的）——第一次这么写直接编译失败。

## 7 Skin/SCP：定义、来源、引入方式

**定义**（`docs/skin-scp-research-20261021.md` §1）：本项目语境下 Skin 是**两个正交轴**——

- **L1 应用级主题**：`ResourceDictionary` + `ThemeDictionaries`（`ThemeType` 亮/暗/跟随 + 品牌 accent 七色阶）
- **L2 播放器控制栏皮肤**：`PlayerStyle` = Standard / Centre / Compact，已存在
- **L3 mpv 进程内 OSC**：**明确不引入**。发布包无 `mpv.exe`，渲染是进程内 composition
  交换链，鼠标以 50 ms 节流转发——OSC 只会叠在画面上和 WinUI 控制栏打架。

**外部方案（联网核实，2026-10-22 实取）**：uosc 3459★/LGPL-2.1；oscc 71★/**无 LICENSE
文件，不可分发**；mpv-osc-modern 431★/LGPL-2.1（活跃下游 ModernZ）；thumbfast
1736★/MPL-2.0。

**引入方式**：`Skins/<Name>/`（**不用 `Themes/`**——它已被 `SliderExt`/`CheckBoxExt` 的
`DefaultStyleKey` + `Themes/Generic.xaml` 框架约定占用），`THIRD_PARTY_NOTICES.md`
新增 `## Skins` 节。

**两个「需真机确认」都跑了，结论都是「不是缺陷」**：

1. 皮肤模板与代码字段不在同一棵树 → 预测「切换后按钮失效」。**实测推翻**：三套皮肤
   下播放键都能翻转 `pause`，且五控件几何各不相同（说明模板确实生效，不是假通过）。
2. `UiFont` 写 `Application.Current.Resources` 可能太晚 → **实测生效**：
   `ShellSettingsText` 行高 33 → Consolas 下 29 → 还原后 33。

两条都保留在报告里，因为按同样的静态推理会再次得出同样错误的结论。
