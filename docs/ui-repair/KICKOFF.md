## 为什么这样写

| 设计 | 原因 |
|---|---|
| 开头就给 `next.py` | 避免开场先做一轮"我理解任务是…"的汇报，直接进入循环 |
| 明确"不要停下来问" | 默认行为是每修一项就请求确认，那样 20 项要 20 次往返 |
| 规则 1 带误判清单 | 这是本任务最容易翻车的地方：把探针问题当产品缺陷，改坏没坏的东西 |
| 规则 2 带实测数字 | `14/19, 14/19, 19/19` 比"应该等元素"有说服力 |
| 规则 3 要求补 BASELINE | 不写"要遵守规范"（无法执行），写"没有依据就先补一条"（可执行） |
| "两次独立运行" | 本仓库间歇性失败率高，一次通过没有意义 |
| 结尾"直到没有可开工项" | 明确终止条件，避免无限循环或过早收工 |
