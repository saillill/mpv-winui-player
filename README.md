# mpv-winui-player

base on [mpv](https://github.com/mpv-player/mpv/) and [WinUI 3](https://github.com/microsoft/microsoft-ui-xaml).

## Limitation

### menu.conf

Some commands aren't supported,  like quit and window related cmd...

### vo

The player use the `d3d11-output-mode=composition` mode, mpv can't get display information.

Use these custom properties as a workaround
```
user-data/mpvw/color-kind : SDR, WCG, HDR
user-data/mpvw/refresh-rate : 60
```
example:
```
[mpvw-sdr]
profile-cond=p["user-data/mpvw/color-kind"] == "SDR"
profile-restore=copy
d3d11-output-csp=srgb
d3d11-output-format=rgb10_a2
```

## Build (local)

Requirements: .NET 10 SDK, Visual Studio Build Tools (C++ workload), Windows App SDK 2.3.x.

```powershell
# builds mpv_winrt (C++/WinRT) with VS MSBuild, then the C# app with dotnet
.\build.ps1 -Configuration Release -Platform x64
```

Output: `mpv-winui\mpv-winui\bin\x64\Release\net10.0-windows10.0.26100.0\win-x64\`

Notes:
- `dotnet build` cannot compile the C++ component (`VCTargetsPath` is a Visual Studio component), so the C# project references the prebuilt C++ outputs from `mpv-winui\bin\<Platform>\<Configuration>\mpv_winrt\` by default. CI builds pass `/p:BuildMpvWinrtWithReference=true` to restore the upstream `ProjectReference` behavior.
- `mpv-2.dll` (libmpv) is downloaded from [ikas-mc/mpv-windows-builder](https://github.com/ikas-mc/mpv-windows-builder) into `mpv-winui\libs\` (see `.github/workflows/build.yml`).

## Configuration layer

`mpv-winui-lazy/` contains the mpv config layer (based on [hooke007/mpv_PlayKit](https://github.com/hooke007/mpv_PlayKit)), including HDR/WCG auto profiles for the WinUI composition renderer, key bindings (`input.conf`), and the `MediaInfo.exe` CLI used by the MediaInfo OSD script. The right-click menu shows the app's fixed File/Window menus plus script-generated dynamic submenus (VSR / RTX Video HDR / shaders); the mpv-lazy `#menu:` data menus are intentionally not shipped.

Deploy to `%LOCALAPPDATA%\mpv-winui\mpv`:

```powershell
powershell -File mpv-winui-lazy\deploy-config.ps1
```

See [mpv-winui-lazy/README.md](mpv-winui-lazy/README.md).

## Localization

- All UI strings (menu bar, player controls, playlist menu, settings, code-created menus) come from `AppLang` (`Modules/Language/AppLang.cs`, English defaults) and are overridden by `Languages\<lang>.json` (en-US / zh-CN shipped). Select the language in Settings (restart required).
- Note: unpackaged WinUI 3 cannot switch `x:Uid`/`x:Bind` resources by language (official issues WindowsAppSDK #3052 / microsoft-ui-xaml #10430), so XAML strings are applied from `AppLang` in code instead of using resw.
- mpv data menus: not shipped (the mpv-lazy `#menu:` data was local customization; see `docs/menu-audit-20260807.md` for the history). The only data menus are the dynamic VSR/RTX-HDR/shader submenus generated by `scripts/dynamic_menu.lua` (labels follow that script).

## Opening files

- Command line (unpackaged): `mpv-winui.exe "path\to\file"` (multiple paths are appended to the playlist).
- URL protocol: `mpv-winui://?file=<url-encoded path>` works when the `mpv-winui` protocol handler is registered on the system (packaged installs register it; unpackaged builds accept the URL from any launcher that already resolved it, and the same activation code also parses it from the command line).
